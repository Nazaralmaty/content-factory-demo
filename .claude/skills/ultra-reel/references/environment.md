# Окружение и грабли

Всё ниже проверено в облачной сессии Claude Code (Ubuntu 24.04, 4 CPU, 15 ГБ RAM, без GPU,
исходящий трафик через прокси с белым списком хостов).

## Что доступно / закрыто

| Ресурс | Статус | Обход |
|---|---|---|
| PyPI, npm, apt (archive.ubuntu.com) | открыто | — |
| fonts.googleapis.com / fonts.gstatic.com | открыто | `scripts/get_fonts.py` (полные TTF со всеми алфавитами) |
| huggingface.co | часто закрыт (403) | `scripts/fetch_whisper.sh` достаёт модель из слоя Docker Hub |
| registry-1.docker.io + auth.docker.io + CDN | открыто | скачиваем слой как tar.gz-поток и вынимаем только нужные файлы |
| ghcr.io | манифесты открыты, блобы (pkg-containers) закрыты | не использовать |
| api.github.com для чужих репо | закрыт | — |

## Модель распознавания

- faster-whisper **large-v3**, `compute_type="int8"`, 4 потока: ~110 с на 42 с аудио.
- Передавай в `transcribe()` numpy-массив 16 кГц, а не путь: свежий PyAV ломает декодер faster-whisper
  (`open() got an unexpected keyword argument 'metadata_errors'`).
- Docker-слой `runpod/ai-api-faster-whisper:dev` весит 14.9 ГБ (все модели подряд по алфавиту);
  large-v3 начинается примерно с 9 ГБ потока. GNU tar при потоковой распаковке оставляет
  симлинки snapshot как пустые файлы-заглушки — поэтому `fetch_whisper.sh` раскладывает блобы
  по содержимому (config.json узнаётся по `alignment_heads` и т.д.).

## Тайминги слов

- Whisper ставит слова с ошибкой до 0.5 с на именах, паузах и хезитациях («Абубакир» растянут
  на 1.6 с, «Ярки Булан» вместо «Еркебулан»).
- `align.py`: гласные транскрипта ↔ пики энергии в полосе 300–2500 Гц (Нидлман–Вунш), границы
  слов — в провалах огибающей. `probe_clips.py` перераспознаёт куски по 1–4 с и подтверждает
  спорные места. Ключевые слова фиксируй руками в `words.json`.
- AV-offset: `ffprobe` → `start_time` аудио. У кружков Telegram аудио стартует на ~20 мс позже
  видео; все тайминги переводим на таймлайн видео.

## Skia (skia-python)

- Нужен `libEGL.so.1` даже для CPU-растра: `apt-get install -y libegl1`.
- `surface.makeImageSnapshot().toarray()` по умолчанию отдаёт **BGRA** — всегда создавай
  поверхности `kRGBA_8888` и вызывай `toarray(colorType=kRGBA_8888_ColorType)` (`gfx.surface/snapshot`).
- `TextBlob.MakeFromShapedText` (HarfBuzz, с кернингом) раскладывает текст от ВЕРХА строки:
  к y нужно прибавлять `font.getMetrics().fAscent` (сделано в `gfx.draw_text`).
- Нет глифа «✓» в Oswald/JetBrains — галочки рисуем путём (`gfx.check_path`).
- Скорость: ~0.3 с/кадр 1080×1920 со всеми эффектами; 4 воркера → 44 с ролика за ~4 мин
  (половина времени — x264).

## Кодирование

- Зерно (σ 5–7) очень дорогое для x264: CRF 15 дал 117 Мбит/с (650 МБ на 45 с).
  Мастер — CRF 18; для отправки — `-crf 20 -maxrate 20M -bufsize 40M` (≈ 40–70 МБ).
- Всегда `-pix_fmt yuv420p -movflags +faststart`, аудио AAC 256k 48 кГц.

## Звук без ушей

Слушать в облаке нельзя, поэтому качество звука доказываем измерениями (`audio_qa.py`):
LUFS/TP мастера, «голос над музыкой» во время речи — полный и «телефонный» (ФВЧ 250 Гц),
спектр по октавам (не должно быть «только саб и шипение»), моно-совместимость (корреляция L/R),
тишина в стопах на графике, DC ≈ 0. Ошибка, которую поймали так: по полному спектру голос был
на 7 LU выше музыки, а на телефоне — на 18 LU (музыка держалась на сабе 40–65 Гц, который
динамик телефона не играет). Лечение: калибровать баланс по «телефонному» взвешиванию,
полка −9.5 дБ ниже 130 Гц на шину музыки, гармоники баса (reese на октаву выше) и щелчок бочки.
